# TeamFlow AI Coding Rules

本项目的目标是**学习和沉淀技术栈**，不是让 AI 代写整个项目。

## 默认原则

### 1. 小步实现

一次只处理一个明确问题，例如：

- 建立 WebSocket
- 保存 Session
- A → B 转发消息
- Android 接收消息

不要一次生成整套聊天系统。

### 2. AI 先解释，再写代码

推荐提示：

```text
先告诉我这个问题需要哪些组件、每个组件为什么存在。
先不要写完整实现。
```

### 3. 明确禁止技术越级

当前任务如果没有明确要求：

- 不主动增加 Kafka
- 不主动增加 Redis
- 不主动增加微服务
- 不主动增加 DDD
- 不主动增加 Outbox
- 不主动增加新的基础设施

### 4. 保留 TODO

代码中可以明确留下：

```java
// TODO: 下一阶段再处理离线消息
```

这样代码会记录学习路线，而不是假装一次就把所有问题解决。

### 5. Review 优先

完成一个小功能后：

```text
先运行
→ 看日志
→ 自己解释
→ 再让 AI Review
```

不要让 AI 直接覆盖掉自己的实现。
